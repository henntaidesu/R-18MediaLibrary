## 1. デスクトップ版と Web 版

Windows アプリと組み込み Web サービスから構成されます。アプリが DB、ディスク上のファイル、取得、スキャン、ローカル再生を担当し、ブラウザーは同じデータを操作します。アプリのプロセスを終了すると Web、ダウンロード、バックグラウンドの更新確認も停止します。

![ライブラリ一覧](assets/manual/home.png)

| 左メニュー | 用途 |
| --- | --- |
| ライブラリ（媒体库） | ライブラリ・サークル・作品からローカルファイルを閲覧 |
| ダウンロード管理（下载管理） | タスク、再試行、取得履歴 |
| 作品検索（作品搜索） | 外部ソースを検索し、取得キューへ追加 |
| 作家の更新確認（作家监控） | FANBOX アーカイブを定期確認して新規投稿をキューへ追加 |
| タグ／サークル／形式（作品标签／作品社团／作品形式） | 取り込み済み作品を別の切り口で閲覧 |
| お気に入り（我的收藏） | 手動で登録した作品 |
| アカウント（账号访问） | FANBOX、pixiv、E-Hentai のログイン状態と認証情報 |
| システム設定（系统设置） | 取得、プロキシ、ライブラリ、画像ホストなど |

各画面右上（またはツールバーの末尾）の **?** ボタンで、その画面に対応するこのマニュアルの章を開けます。システム設定では各区分の見出しにも **?** があります。

**Web のパスはアプリを動かしている PC のパスです。** スマートフォンから `D:\Media` を入力しても、指定先はサーバーの D ドライブです。取得先もサーバーになります。

| 機能 | デスクトップ | Web |
| --- | --- | --- |
| 閲覧、分類、お気に入り、キュー、更新確認 | 対応 | 対応 |
| フォルダー追加 | OS のフォルダー選択 | サーバーの絶対パスを入力 |
| 音声・動画再生 | LibVLC／NAudio | ブラウザーの対応形式に依存 |
| asmr.one と SOU 優先ソース | 設定と直接取得入口あり | 現在専用入口なし。共通キューは閲覧可能 |
| E-Hentai のサイト・画質、pixiv の区分・一致方法・画質 | 設定可能 | サーバー設定を利用 |
| 外部アクセス・ポータル SSO | 設定可能 | 外部アクセスの状態表示のみ |
| ゲーム | ローカル実行 | サーバー実行または配信を要求 |
| 画像翻訳 | 設定と依存管理。第 17 節参照 | 翻訳操作入口なし |

## 2. インストール・起動・初期設定

### 2.1 ソースから実行

Windows と .NET 10 SDK が必要です。リポジトリのルートで実行します。

```powershell
dotnet build src/R-18MediaLibrary.csproj
dotnet run --project src/R-18MediaLibrary.csproj
```

ルートの `start.bat` をダブルクリックしても起動できます。プロジェクトへ移動し Release 構成で実行します。初回ビルドでは依存関係を復元します。

### 2.2 発行済みアプリ

`publish.bat` で `publish/R-18MediaLibrary.exe` を生成します。古い `publish` フォルダーは先に消去されるため、個人の DB や作品を置かないでください。実行先には .NET 10 Desktop Runtime が必要です。exe 隣の `libvlc/win-x64/` を保持します。

### 2.3 初回の順序

1. 「システム設定 → ダウンロード」でキャッシュパスを確認します。
2. ライブラリを作り、完成作品の保存先を追加します。第 3 節参照。
3. 必要ならプロキシを設定し、サーバーから接続できることを確認します。
4. ソースごとにアカウントを設定します。掲示板のホスト解析には Debrid-Link API Key が必要です。他の直接取得ソースでは使用しません。
5. 既存ファイルを先に取り込み、閲覧確認後に少数の作品を取得します。
6. スマートフォンで利用するならデスクトップから外部アクセスを有効にします。

通常の設定は選択変更または入力欄からフォーカスが外れた時に保存されます。一括保存ボタンはありません。アカウント画面は「保存して確認（保存并检测）」を使います。

## 3. ライブラリ作成とローカル作品の取り込み

### 3.1 作成

1. システム設定内のライブラリを開きます。
2. 「新規ライブラリ（新建媒体库）」で名前（例：音声）を入力します。
3. フォルダーを追加します。Web では `D:\Media\Audio` などサーバー上に存在する絶対パスを指定します。
4. 一覧のカードから閲覧、右上の `⚙` から個別設定を開きます。

![個別ライブラリ設定](assets/manual/libsettings.png)

ひとつのライブラリに複数フォルダーを関連付けられます。名前は論理的な分類、フォルダーは実体です。「初期表示（默认显示）」で作品／サークルを選ぶと、次に開いたときに最初に表示されるビューが決まります。

### 3.2 フォルダー構成

スキャンはデータソース**直下の子フォルダーだけ**を検査します。名前に `RJ` と 6 桁以上の数字、または `FB`／`EH`／`PX` と数字が必要です。

```text
D:\Media\
├─ RJ123456\                 DLsite 作品
│  ├─ DataSource\            表紙・説明などのメタデータ
│  └─ Audio\
├─ FB12345678\               FANBOX 投稿
├─ EH1234567\                E-Hentai ギャラリー
└─ PX123456789\              pixiv 作品
```

`D:\Media\Circle\RJ123456` の構成なら Circle を登録するか、階層を整理します。検索が RJ/BJ/VJ に対応していても、現在のスキャン正規表現に BJ/VJ は含まれません。

### 3.3 スキャンとメタデータ

| 操作 | 動作 | 用途 |
| --- | --- | --- |
| 全ソースをスキャン（扫描全部数据源） | フォルダーがある全ライブラリを順番に処理 | 初回取り込み、大量追加 |
| メタデータをスキャン（扫描元数据） | 対象を走査、新規取り込み、見つからない記録を整理し、必要な情報を補完 | 日常同期 |
| メタデータを再スキャン（重新扫描元数据） | 上記に加え、情報を強制的に再取得 | 欠落・古い情報や表紙の修復 |

完了表示を待ちます。画面を離れて戻っても処理は継続し、後続要求は待ち行列に入ります。通信失敗時は接続を確認して対象ライブラリを再試行します。

**スキャンは見つからない作品の記録も整理します。** データソースのルートにはアクセスできるのに、その中の作品フォルダーがなくなっている場合、その作品の記録は削除されます。ルート全体にアクセスできない場合（ネットワークドライブの切断、外付けドライブの未接続など）はそのルートの整理を飛ばすため、誤って消えることはありません。作品フォルダーを一時的に改名・移動しているだけなら、元に戻してからスキャンしてください。

### 3.4 名前・パス・削除

- **名前変更：** `⚙ → 名前` を変更すると、作品の所属、取得先、更新確認先の名前も更新します。
- **フォルダー編集：** 実ファイルの移動やドライブ文字変更後に使います。存在する新パスを指定し、保存済みパスの接頭辞を更新します。データソース全体を自動移動する機能ではありません。
- **フォルダー解除：** ライブラリ設定から外し、後のスキャン範囲を変更するだけです。そのフォルダーから取り込んだ作品の記録は削除されず、ライブラリに表示され続け、以後のスキャンでも整理されません。不要な作品は詳細画面から個別に削除してください。
- **ライブラリ削除：** 設定を削除します。ダイアログの説明どおり実ファイルと取り込み済み記録は保持され、作品削除とは異なります。これらの作品は所属ライブラリが空になり、どのライブラリカードにも表示されなくなりますが、トップの検索や「タグ／サークル／形式」からは引き続き見つけられます。

## 4. 閲覧・検索・分類

### 4.1 ライブラリ内

1. ライブラリカードを開きます。
2. サークル表示ならサークルを選びます。
3. 上部の「作品表示／サークル表示（显示作品／显示社团）」で切り替えます。
4. 並べ替えを選択します。
5. 作品カードで詳細へ進み、左上の「戻る（返回）」で前の階層へ戻ります。

### 4.2 既存作品を検索

トップ、ライブラリ内、タグ・形式グループ内の範囲検索は、サーバー側で作品番号と名前を照合します。トップは全体、ライブラリ内はその範囲です。具体的な作品一覧ではカードのローカル絞り込みにサークル名も含まれます。入力例にサークルとあっても全階層で検索できるとは限りません。サークルを探す場合はサークル一覧を使います。入力を空にすると元に戻ります。

左メニューの作品検索は外部ソース用です。取り込み済み作品はライブラリの検索欄を使います。

### 4.3 分類・サークル・お気に入り

![作品形式](assets/manual/types.png)

タグはタグ別、サークルは全ライブラリのサークル別、形式は保存済みメタデータ別にまとめます。順に開くと作品へ進めます。形式名は日本語のまま、または似た表記が別々に残る場合があります。

サークルカード右上の編集では別名、FANBOX、pawchive のホームページを指定できます。別名は表示用で、作品記録の実サークル名は変更しません。ホームページリンクは直接開けます。

お気に入りは詳細画面のスイッチで管理し、ファイルは複製しません。

## 5. 詳細・お気に入り・ファイル管理

詳細は「タイトル → 折りたたみ可能な作品情報 → ファイル」の構成です。作品フォルダーがある場合は情報を初期状態で折りたたみます。「作品詳細（作品详情）」を開くと表紙、番号、サークル、発売日、タグ、本文を表示します。作品フォルダーがない場合は展開した状態になります。

タグ、声優、シリーズなどのリンクで絞り込めます。作品番号のリンクは常に DLsite の作品ページを指すため、有効なのは DLsite 作品だけです。FANBOX・E-Hentai・pixiv の作品では対応するページがありません。

| 操作 | 影響 |
| --- | --- |
| ☆／★ 既読（已读） | マーカーを切り替え、ファイルは移動しません |
| ♡／♥ お気に入り（收藏） | お気に入りへ追加・解除 |
| ライブラリへ移動（移动媒体库） | 作品フォルダーがある場合のみ表示。保存先を選んで確認すると実フォルダーを移動し、記録を更新 |
| 作品削除（删除作品） | 実フォルダー、DB、関連取得記録・キャッシュなどを削除。現在は復元不可 |

移動前は空き容量と使用中ファイルを確認します。削除は非表示化ではありません。作品名を確認してください。

既読、取得履歴の `已品悦`、ユーザーが作った「聴取済み」ライブラリは別の概念です。ソースでは `已品悦` をライブラリ表示対象の状態として使い、ローカル取り込みや展開後の登録でも設定します。実際に読んだ・聴いたことを示すとは限りません。ライブラリ名やこの状態だけで閲覧の進み具合を判断しないでください。

## 6. 画像・音声・動画

### 6.1 ファイル閲覧

詳細の下に「作品ファイル（作品文件）」があります。「サムネイル（缩略图）」と「ファイル一覧（文件列表）」を切り替えます。サムネイルは画像向けで、一覧は名前、サイズ、折りたたみツリーを表示します。サムネイルではフォルダーを開き、一覧では行を展開します。

### 6.2 画像

クリックすると拡大します。Web では左右に切り替えられ、タッチ操作は左スワイプで次、右で前、上下で終了です。Esc、閉じる、背景クリック、ブラウザーの戻るでも終了します。戻るはまず画像を閉じ、作品から直接離れません。同階層の画像が対象となり、子フォルダーは別に開きます。

### 6.3 音声

クリックで下部プレイヤーを開き、同階層を名前順のキューにします。一時停止、前後曲、シーク、プレイリスト選択に対応します。約 3 秒以上再生している場合や最初の曲の場合、前曲操作は現在曲の先頭に戻ります（両版共通）。

スリープタイマーは版によって異なります。

- **Web 版：** 15／30／45／60／90 分の既定時間、任意の分数、「現在曲終了まで（播放完当前）」を選べます。**時間到達後も現在曲を最後まで流し、次曲への継続を止めます。** 即座には切りません。
- **デスクトップ版：** 15／30／45／60／90 分の既定時間のみです。**時間到達と同時に一時停止**し、再生位置は保持されるので続きから再生できます。

デスクトップの NAudio は音量正規化も行います。

### 6.4 動画とその他

動画クリックでプレイヤーを開き、同階層を連続再生します。デスクトップは LibVLC、Web はブラウザーのコンテナー・コーデック対応に依存します。デスクトップで再生できても Edge で再生できるとは限りません。

その他のファイルはブラウザーで URL を開き、プレビューか保存かは種類とブラウザー次第です。`.exe` は第 16 節参照。

## 7. DLsite と Anime-sharing の取得

![作品検索](assets/manual/search.png)

### 7.1 検索

1. 作品検索で DLsite を選びます。
2. RJ/BJ/VJ、RG サークル番号、DLsite リンクを入力し「検索（查询）」または Enter。
3. 単作品はソース結果、サークル・一覧は作品グリッドを開き、下へ進むと追加読み込みします。

現在の Web 入力は任意タイトルの全文検索を保証しません。番号かリンクを優先します。

### 7.2 中継設定

掲示板投稿からホストリンクを抽出し、Debrid-Link で解析します。「システム設定 → Debrid-Link 中継（Debrid-Link 下载中转站）」へ自分の有効な API Key を入力し「テスト（测试）」で確認します。対応ホストと利用枠はサービスの応答によります。

### 7.3 取得方法

| 方法 | 手順 |
| --- | --- |
| 手動 | 投稿結果を開き、抽出と検査を待ち、有効ホスト群を選んで保存先を指定 |
| 組み合わせ（组合下载） | 投稿結果の「組み合わせ」をクリック。Rapidgator 優先。同名の分割ファイルを別ホストで補い、完全な構成だけキューへ追加。不足は通知 |
| 単作品の自動取得 | 掲示板スキャンで投稿が見つかった（`AS·N帖` 表示）後、カードの「自動取得（自动下载）」で保存先を選ぶと、バックグラウンドで検索・検査・解析。それまではボタンが無効 |
| グリッド全体の自動取得 | ツールバーで有効化し保存先を一度選択。対象と後続ページを処理するため、大量タスクになる場合あり |

カードは未スキャン、`AS·N帖`、`AS·无`、不要、待機、取得中、取得済み、`已品悦` などを示します。投稿が見つかってもファイルの完全性・有効性は保証しません。不要指定は処理したくない作品を飛ばします。

過去に追加した作品は確認が出る場合があります。履歴で重複を確認し、追加後は管理画面で進捗を見ます。

## 8. asmr.one の直接取得

この手順は**デスクトップ版**向けです。音声・ASMR（SOU）用で、Debrid-Link は使いません。

1. 設定 → ASMR.ONE にアカウント・パスワードを入れ「ログインテスト（登录测试）」を実行。
2. ミラーと mp3、flac、wav、画像、字幕などの形式を選びます。
3. 「作品種別の優先ソース（作品类型优先搜索）」で SOU を asmr.one にします。
4. RJ 番号で SOU を検索します。
5. 直接取得バナーから保存先を選びます。

アカウント設定済みで作品がない場合は Anime-sharing に戻ります。未設定でもバナーが出る場合がありますが、取得時に設定が必要で、存在確認済みとは限りません。直接取得は階層を保持します。

Web 検索に同じバナーや呼び出し入口はありません。デスクトップで作ったタスクは共通の Web キューから確認できます。

## 9. FANBOX アーカイブと公式ソース

### 9.1 違い

| 表示 | ソース | 条件 |
| --- | --- | --- |
| FANBOX | pawchive アーカイブ | FANBOX ログイン不要 |
| FANBOX（アカウント名） | fanbox.cc 公式 | アカウント画面で保存・検証済みのログイン |

公式はアカウントが閲覧できる範囲だけを取得します。「支援が必要（需赞助）」は権限不足を示し、取得ボタンは無効です。

### 9.2 検索・確認・取得

1. ソースを選び、作家名、ID、対応する作家リンクを入力します。
2. 検索します。アーカイブ初回は作家索引を取得するため時間がかかる場合があります。
3. 複数候補なら選択し、単独候補なら直接開く場合があります。
4. 表紙・タイトルで本文、画像、添付、対応する外部ファイル情報を確認します。
5. 単件はカードか詳細ツールバーの取得、複数は「選択（选择）→ 選択分を取得（下载选中）」。
6. 保存先を選び、追加・スキップ数を確認して管理画面へ進みます。

全選択は現在読み込み済みで選択可能な投稿だけです。追加読み込み後は件数を確認します。カード本体は詳細を開く操作で、選択とは別です。取得済み・取得中でも閲覧できますが再選択はできません。

公式で空欄検索すると支援・フォロー中の作家を表示できます。ソース切り替えでは対象データがリセットされ、両者の結果は混在させません。

### 9.3 保存ファイル

`FB<投稿ID>` に保存し、画像は順番で採番します。添付は通常、連番を付けて元名を保持します。対応する外部共有ファイルは展開してタスク化し、自動展開が有効なら圧縮添付を階層ごとに解凍し（書庫の中の書庫も続けて解凍）、中身は途中のフォルダーを残さず作品のルートへ平らに置きます。同名ファイルは上書きせず `_2`、`_3` を付けます。解凍できた書庫は削除し、開けない書庫はそのまま残して作品は通常どおり登録します。有効性はリンクとソースの対応次第です。

完了後は共通ライブラリで閲覧します。検索画面に独立したローカル FANBOX 庫はありません。更新確認は第 12 節参照。

## 10. E-Hentai と pixiv

### 10.1 E-Hentai／ExHentai

1. デスクトップ設定でサイト・画質を選び、必要なら接続確認します。
2. 権限が必要な場合はアカウント画面で設定します。
3. E-Hentai を選び、キーワード、`artist:名前` などのタグ、ギャラリー URL を入力。
4. カードで詳細・タグを確認し、取得／「この作品を取得（下载本篇）」、または選択分を一括取得。
5. 保存先を指定し、完了後 `EH<ギャラリーID>` を開きます。

原画はソースの対応が必要です。未ログイン時は表示用画像に切り替えられます。ExHentai は権限と有効な Cookie に依存します。

### 10.2 pixiv

1. 対象に応じて pixiv にログインします。
2. デスクトップ設定で画質、検索区分、タグ一致方法を選びます。
3. pixiv でキーワード、タグ、作品リンクまたは番号を検索。
4. カードで詳細、または選択／取得・選択分取得でキューへ追加。
5. 完了後 `PX<作品ID>` を閲覧します。

未ログインでは R-18 を除外する場合があります。ソース選択できてもログイン有効とは限りません。プレビューは原画の取得完了を意味せず、原画は取得処理で読み込みます。

## 11. キュー・展開・履歴

![ダウンロード管理](assets/manual/download.png)

### 11.1 開始・停止・進捗

名前や矢印でファイル・分割構成を開き、進捗、速度、状態、エラー、リンクコピーを確認します。直接取得の階層は保持します。

「開始（开始下载）」でエンジンを動かし、「一時停止（暂停下载）」へ変わります。「停止中（暂停中…）」は終了処理中です。作品ごとの取得／停止も状態に応じて表示します。再開はソースの Range 対応に依存します。

設定の自動取得はエンジン関連、検索グリッドは一括タスク作成、更新確認は新投稿の発見であり、それぞれ別です。

### 11.2 再試行と整理

| 操作 | 影響 |
| --- | --- |
| 再解析（重新解析） | 失敗タスクの新しい取得アドレスを取得 |
| 全件再解析（全部重新解析） | 解析失敗・有効リンクなしを再投入し、現在の実装ではエンジンも開始 |
| 再検索（重新搜索） | 失敗タスクがある場合のみ表示。確認後、**作品フォルダー（取り込み済みでも）、取得記録、作品記録（`已品悦` を含む）を削除**して検索へ戻る。復元不可 |
| 完了分を整理（清除已完成） | 完了と元ファイルなしの終端行を除去。展開中は保持 |
| リンクなしを整理（清除无可用连接） | 失敗の仮タスクと未確定の仮作品記録を整理 |
| 全リスト消去（清空列表） | キュー行と対応する仮記録を整理。一時停止ではない |
| タスク行の削除（删除） | タスクを止めて除去。未登録の作品は作品記録も削除し、登録済み（`已品悦`）の作品はキューから外すだけでライブラリに残ります。削除するのは取得キャッシュ内のフォルダーだけ。ライブラリの作品削除とは別 |
| 作品へ移動（跳转作品） | 記録がある場合にライブラリ詳細を開く |

無効表示は適用対象がない場合が一般的です。一時的な停止は一時停止を使い、消去や削除で代用しないでください。

### 11.3 利用枠とパラメーター

右上 Debrid-Link カードでホスト別利用枠・上限到達を確認できます。中継ソースのみが対象です。速度低下や制限では先にファイルのエラーを開きます。

ファイル単位のスレッド数は 1～6、最低速度と全体制限は KB/s、制限 0 は無制限です。スレッド数は同時作品数ではありません。制限が続く場合は並列度を下げて回復を待ちます。

### 11.4 自動展開

有効時はインストール済み Bandizip または組み込み SharpCompress を使い、入れ子整理、一部の文字コード修正後に登録します。

暗号化された書庫は同じ場所の説明ファイルからパスワードを試し、次に設定のパスワード一覧を使います。＋で追加、削除時は確認があります。失敗時は分割不足、パスワード、容量、使用中、文字コードを確認し、再取得だけを繰り返さないでください。

### 11.5 取得履歴

「取得済み（已下载）」から履歴へ進み、番号・名前・サークルで検索できます。取得中／取得済み／`已品悦` の絞り込み、見出しでの並べ替え、更新、取得済み記録を `已品悦` に変更、作品への移動が可能です。「← ダウンロード」で戻ります。

## 12. 作家の更新確認

![作家の更新確認](assets/manual/watch.png)

現在は **pawchive FANBOX アーカイブ作家**向けで、公式購読の巡回ではありません。

1. 作品検索 → FANBOX で作家を開きます。
2. 「作家を監視（+ 监控作家）」から保存先を指定。追加後、ボタンは「監視中（✓ 已监控）」に変わります。
3. 「全部取得（全部下载）」なら既存もキューへ、「新規のみ（只要新作品）」なら今後を対象にします。
4. 更新確認画面で保存先、間隔、次回時刻を確認します。

全体スイッチが自動巡回を制御し、オフでも「今すぐ確認（立即检查）」は使えます。既定と個別の間隔を調整できます。各カードは手動確認、一時停止・再開、作家ページ、削除、前回結果、累計を提供します。

監視削除で取得済み作品は削除しません。アプリを起動し、保存先を利用可能にしてください。新投稿発見と取得完了は別なのでキューも確認します。

## 13. アカウント

FANBOX、pixiv、E-Hentai を管理します。Web パスワードと asmr.one は対象外です。

| サイト | 対応情報 |
| --- | --- |
| FANBOX | `FANBOXSESSID` |
| pixiv | `PHPSESSID` |
| E-Hentai | `ipb_member_id`、`ipb_pass_hash`、`igneous`、または ID・パスワードから Cookie 取得 |

FANBOX／pixiv は自分のブラウザーでログインし、画面の説明に従って F12 → Application → Cookie から該当名の値を入力、「保存して確認（保存并检测）」で有効性を確認します。

E-Hentai は自分の ID・パスワードで「ログインして Cookie 取得（登录并获取 Cookie）」、または既存 Cookie を保存・検証します。

入力欄は書き込み専用で保存済み値を表示しません。再読込後に空でも消失ではなく、空欄は元値を保持します。「確認（检测）」は検証、「ログアウト（退出登录）」は情報削除です。期限切れは自分の有効情報を取得し直します。DB に認証情報があるため、Cookie、Key、DB を公開画像やリポジトリへ含めないでください。

## 14. 設定と表紙用画像ホスト

### 14.1 設定項目

| 分類 | 内容 |
| --- | --- |
| ダウンロード | キャッシュ、自動取得・展開、スレッド、最低速度、制限、パスワード |
| プロキシ | 有効、種類、ホスト、ポート。外部ソースへのアクセスに使用 |
| Debrid-Link | Key と確認。保存済み値はマスク |
| システム | 言語、ログ、展開文字コード。デスクトップは閉じる動作も設定 |
| ライブラリ | 作成、保存先管理、スキャン |
| 画像ホスト | URL、プロジェクト、Token、確認、表紙移行 |
| 外部アクセス | デスクトップで設定、Web は状態のみ |

簡体字・繁体字中国語、日本語、英語を選べます。調査時は一時的にログレベルを上げ、`log/` を確認します。文字コードは既定 `cp437`、実際の文字化けがある場合に調整します。

Web の Debrid-Link Key 表示ボタン（目のアイコン）はアクセス用パスワードを要求します。普段は表示不要です。Key や Token の空欄は通常「変更なし」で、消去ではありません。

### 14.2 画像ホスト

1. 対応する自前サービス、プロジェクト ID、Token を用意。
2. 値を入力し「接続確認（测试连接）」を実行。
3. 成功後に有効化し、既存は「表紙移行（迁移封面）」を利用。
4. 完了を待ち、ライブラリで表示を確認します。

表紙・サムネイルを配信して HDD のランダム読み取りを減らします。音声・動画・添付全体の移動ではありません。失敗時は接続と設定を確認し、ローカルデータを残します。

## 15. Web アクセスとポータルログイン

### 15.1 LAN

1. デスクトップの外部アクセスでポート・パスワードを設定し有効化。
2. 待受状態を確認。
3. 同一ネットワークで `http://<ホストのLANアドレス>:<ポート>/` を開きます。既定は 8080、実設定を優先。
4. ログイン画面ではプロジェクトのアクセス用パスワードを使います。

不通ならホストの localhost を先に確認し、次に IP・ポート・通信・ファイアウォールを確認します。別端末の localhost はサーバーではありません。

### 15.2 ポータルと SSO

今回の画面は既存ポータル経由です。ドメイン、クライアント ID、プロキシのサブパスは導入環境の値で、既定ではありません。

「ポータル SSO（门户单点登录）」に有効化、Client ID、ポータル URL、内部 URL、Client Secret、ユーザー一覧があります。導入者は発行された値とコールバックを確認して「ポータルログイン（门户登录）」を使用します。URL だけでは設定完了になりません。

Web の一部要求と配信用 WebSocket はルート `/api/...` を使います。**サブパス公開ではゲートウェイの転送設定が必要です。** トップ画面だけで全 API・配信の接続確認済みとは言えません。本書で SSO 再設定や配信テストはしていません。

## 16. ゲーム実行とリモート配信

1. ファイルの `.exe` を開き「ローカル実行（本机运行）」か「リモート配信（远程串流）」を選択。
2. ローカル実行は**サーバー Windows**を指し、ブラウザーが別 Windows PC でも同じです。非 Windows 端末では選択肢が灰色表示になり、選べません。
3. 配信はホストの画面を送り、キー・マウス・タッチ入力を返します。

方向、Z、X、Enter、Esc、Shift、Ctrl、空白、Tab などのタッチキーがあり、音声と全画面も切り替えられます。同時に 1 接続のみで、新接続が引き継ぎます。

画面を閉じたり切断しても**プログラムは終了しません**。再接続で継続できます。閉じるときは「プログラム終了（结束程序）」を使います。ホストには操作可能な Windows デスクトップと通常のアプリウィンドウが必要です。

画面待ちならホストの起動、切断なら WebSocket と転送、特にサブパスを確認します。

## 17. 画像翻訳の実装範囲

モデル区分、CPU／GPU、モデル場所、文字入れ用フォント、依存取得・中止・削除がデスクトップにあります。不足時は有効化できず、未取得の区分・場所へ変えると停止します。訳画像は作品内 `translated/` に保存する設計で、原画を上書きしません。

**実際の画像翻訳実行と表示入口は未接続です。** `TranslateService` は準備判定とパス規則を担当し、全体確認でビューアー・詳細から OCR、翻訳、文字入れを実行する処理、対応 Web API は見つかっていません。

依存管理の実装として理解し、「モデル取得・有効化で自動翻訳ができる」とは扱わないでください。通常利用にモデルは不要です。

## 18. バックアップ・移行・トラブル対処

### 18.1 バックアップと移行

正常終了しタスク停止を確認して、使用中の `R-18MediaLibrary.db`、全ライブラリ（`DataSource` を含む）、代替 `images/` を保存します。必要に応じキャッシュ、モデル、ログも保持します。

SQLite は WAL を使い、実行中の `.db` だけのコピーは未統合データを漏らす場合があります。終了後のコピーを優先し、オンラインは SQLite の整合性を保つ方法を使います。認証情報が含まれる DB は非公開として扱います。

DB は作業ディレクトリ、exe から上位の順で検索し、ない場合だけ exe 隣に作ります。移行前に実ファイルを確認してください。新名がなければ旧 `DLsiteMedia.db`／`DASD.db` から移行を試みるため、先に保存します。

ドライブ変更時は実ファイルを復旧、ライブラリのパス編集、ファイル閲覧確認、その後スキャンの順です。使えない旧場所を先に走査しないでください。

### 18.2 よくある問題

| 現象 | 最初の確認 |
| --- | --- |
| .NET 不足 | 発行版は Desktop Runtime 10、ソースは SDK 10 |
| 取り込み 0 件 | サーバーのパス、直下の子フォルダー、RJ/FB/EH/PX |
| ドライブ移行後に開けない | パス編集、実行ユーザーの権限 |
| 情報・表紙が不足 | ソース通信、プロキシ、進捗、必要なら再スキャン |
| ローカル作品が見つからない | 範囲、トップへ戻りフィルター解除 |
| FANBOX 公式がない | ログイン保存・検証後、検索へ入り直す |
| pixiv の結果不足 | ログイン、区分、一致方法、閲覧権限 |
| ホスト解析失敗 | Key、対応、利用枠、リンク失効 |
| 有効リンクなし | 投稿だけでは不十分。エラー・分割を確認して再解析 |
| タスク停止 | エンジン、個別停止、解析・待機、容量 |
| 100% でも閲覧できない | 展開待ち・失敗、登録未完了 |
| 展開失敗 | パスワード、説明ファイル、分割、空き容量、使用中、文字コード |
| Web だけ再生できない | コーデック。デスクトップか対応形式を使用 |
| 更新確認が動かない | プロセス、全体スイッチ、停止、間隔、通信、保存先、キュー |
| スマートフォンで開けない | ホスト起動、外部アクセス、IP、ポート、通信、ファイアウォール |
| ポータルの一部だけ失敗 | ルート API と WebSocket の転送 |
| モデル取得済みでもボタンなし | 依存管理までで翻訳実行は未接続 |
